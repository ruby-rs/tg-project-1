# Пилот на реальных объектах

Цель пилота — за 2 недели на 1–2 прорабах понять три вещи:

1. **Справляется ли расшифровка** с голосовыми со стройки: шум, техника, мат, жаргон.
2. **Полезны ли отчёты** руководителю: есть ли в них объёмы, проблемы и риски, нет ли выдумок.
3. **Будут ли прорабы пользоваться ботом** каждый день без напоминаний руководителя.

По итогам решаем: какую модель Whisper и LLM оставить (локальные или внешний API),
что доработать перед подключением первых платных клиентов.

## Подготовка (день 0)

- [ ] Сервер обновлён до последней версии: `git pull && docker compose up -d --build`,
      `docker compose ps` — все сервисы `running`, `migrate` — `exited (0)`.
- [ ] В `.env` заполнены `PD_OPERATOR`, `PRIVACY_POLICY_URL`, `SUPPORT_CONTACT`
      (см. [PERSONAL_DATA.md](PERSONAL_DATA.md)).
- [ ] Бэкап настроен и проверен: `scripts/backup.sh` отработал, в cron есть задача.
- [ ] Руководитель прошёл весь путь сам: `/start` → компания → `/new_object` →
      фото, голосовое, текст → `/report` → `/archive`.
- [ ] Объекты пилота созданы, у каждого задан адрес (`/sites` → объект → «📍 Адрес»):
      адрес попадает в отчёт.
- [ ] `/settings`: время сводки и напоминания, рабочие дни, часовой пояс.
- [ ] Прорабам отправлены ссылки на их объекты (`/invite` → объект) и памятка ниже.

## Метрики и цели

Всё, кроме опроса, видно в `/stats` (последние 7 дней).

| Метрика | Где смотреть | Цель пилота |
|---------|--------------|-------------|
| Прораб присылает сообщения каждый рабочий день | `/stats` → «Активность прорабов» | ≥ 4 дней из 5 |
| Доля исправленных расшифровок | `/stats` → «Исправлено прорабами» | ≤ 20% |
| Оценки отчётов | `/stats` → 👍 / 👎 и замечания | 👍 ≥ 70% |
| Время сборки отчёта | `/stats` → «Среднее время сборки» | ≤ 2 мин (внешний API) / ≤ 10 мин (локальная модель) |
| Необработанные сообщения | `/stats` → «Не обработано» | 0 (после «🔁 Повторить») |
| Руководитель читает вечернюю сводку | опрос в конце пилота | «да, каждый день» |

Если расшифровки исправляют чаще чем в 20% случаев — пробуем модель Whisper крупнее
(`WHISPER_LOCAL_MODEL=medium`) или внешний API. Если много 👎 с замечаниями
«выдумал» / «не тот объём» — меняем LLM на более сильную.

## Ход пилота

**Каждый день (5 минут, руководитель):**
- прочитать вечернюю сводку, по одному объекту открыть «📋 подробно»;
- поставить 👍 или 👎 под отчётом, при 👎 — коротко написать, что не так;
- если пришло «❌ Не удалось…» — переслать разработчику.

**Раз в неделю:**
- `/stats` — сохранить скриншот;
- выгрузить архив за неделю (`/archive` → «7 дней») и проверить, что в нём есть всё,
  что присылали прорабы;
- созвониться с прорабами: что неудобно, чего не хватает.

**Технический контроль (разработчик):**
```bash
docker compose logs --since 24h worker | grep -iE "error|traceback" | tail -20
docker compose exec db psql -U foreman foreman -c \
  "select status, count(*) from entries group by status;"
docker compose exec db psql -U foreman foreman -c \
  "select comment from report_feedback where rating < 0 and comment is not null order by updated_at desc limit 20;"
```

## Памятка прорабу

Текст можно переслать прорабам как есть:

> **Как работать с ботом-отчётом**
>
> 1. Перейдите по ссылке от руководителя и нажмите «Согласен».
> 2. В течение дня присылайте боту всё, что происходит на объекте:
>    - 🎙 **голосовые** — что сделали, сколько (кубов, квадратов, метров), что мешает,
>      что нужно завезти. Бот пришлёт расшифровку — если в ней ошибка, ответьте на неё
>      исправленным текстом;
>    - 📷 **фото** — работы до и после, скрытые работы (арматура до бетона), проблемы.
>      Важные фото для споров с заказчиком отправляйте **файлом** — так сохранится
>      дата съёмки;
>    - ✏️ **текст** — если удобнее писать.
> 3. Ошиблись в тексте или подписи — просто отредактируйте сообщение, бот учтёт правку.
> 4. `/report` — посмотреть отчёт за сегодня, `/report вчера` — за вчера.
> 5. Работаете на другом объекте — `/object` и выберите его.
>
> Вечером руководитель получит сводку по всем объектам. Если за день от вас ничего
> не было, бот напомнит.
